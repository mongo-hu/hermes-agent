## 哪些已落地，哪些是目标

| 内容 | 文档口径 |
| --- | --- |
| 本地 EXE `capabilities`／`analyze --request`、现有规则求值和异步报告入口 | 代码静态核对基线；部署指南和运行手册列出核对入口，不代表本机 E2E 已通过 |
| `dfm.geometry/v2` 常驻会话、一次模型导入、两轮分组增量编排 | 目标设计；正式 Schema、两端实现及联调尚待完成 |
| 171 条来源需求、44 条 A 类映射、48 个任务包 | 需求与建议分工，不是已发布能力数量；本次可执行范围看实际 capabilities、规则和输入 |
| 算法工程认证与生产可用 | 以具体构建、样本和验收记录为准，不由文档的 active 状态推定 |

本体发布包 Schema、几何通信协议、显示制品 Schema 是不同版本体系。新发布规则采用 Schema 4 的 OR-of-AND 判定；现有 Agent 仍可读取历史规则包。规则包兼容读取不等于为新 Worker 协议增加旧路由兼容层。

## 文档怎么维护

- 全流程和系统职责只在主流程维护；专项文档引用它，不再各画一份完整流程。
- G 的工程语义以审核后的本体发布物为准，候选 ID 不当作已发布能力。字段、规则和本地投影在规则契约维护。
- 公共几何消息以 Worker 角色文档及后续统一发布的 Schema／样例为准；Hermes 文档说明消费方式，不手写第二套协议。当前目标 Schema 尚未交付。
- 实现状态更新需附代码入口或提交、契约／构建版本和验收记录。仅修改文档日期不表示代码已完成。
- 需求只在统一台账逐行维护，映射文档维护工程定义，任务文档维护交付与验收；用来源编号和任务 ID 关联。
