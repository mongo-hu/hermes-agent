## 开发和测试如何使用

开发人员按本次任务和当前契约确定改动范围，会话文档第 11 节的旧改造记录仅供追溯；测试人员按任务范围选用任务清单中的 FLOW-01—12 建立用例。任务清单末尾提供命令、样件要求和验收记录格式；通过数量只对该次构建和已执行范围有效。

先在独立测试项目中检查源码与 EXE 的契约版本，再跑专项和全链路。单轮审核交互的既有验收记录在会话文档第 11.4 节；恢复契约与等待反馈见第 10.21、10.23 节，第 15 节保留 2026-11-06 的适配记录。当前发布消费范围见规则契约第 9 节，不能沿用旧版本通过记录或将预览的演示候选当作真实算法结果。安装与版本不匹配的排查见部署指南。

## 文档怎么维护

- 全流程和系统职责只在主流程维护；专项文档引用它，不再各画一份完整流程。
- G 的工程语义以审核后的本体发布物为准，候选 ID 不当作已发布能力。字段、规则和本地投影在规则契约维护。
- 结构名称统一使用“带孔 Boss 柱”，Worker 类别为 `hollow_boss`，本体概念为 `FEATURE_HOLLOW_BOSS`；规则匹配不要求确认功能用途。旧名称和旧 ID 仅在历史归档或原始来源引用中保留，不能作为当前接入示例。
- 公共几何消息由 Worker 仓库统一维护；可执行格式见 `schemas/session-v2.schema.json`、`schemas/protocol-versions.json`。当前随包目录为 bundle 2.6.0；消费者同时接受 2.5.0，但新外观能力须以实际声明核对。其他机器仍须核对握手，不能混用安装包。Hermes 文档说明消费方式，不手写第二套协议。发布时同步源码、EXE、运行库和 Schema。
- 主流程采用一轮识别；保留按依赖的内部任务及修订后的定向重评，不把固定倒扣补识别当成必经第二轮。面索引由 Worker 在内部维护且不外传；Hermes 保存公开语义投影，Desktop 按正向面引用建立导航。
- 开发先看主流程的数据泳道与阶段表，再按任务看 Hermes 会话文档第 9.6、9.7 节或 Worker 会话文档第 2.2 节成型职责、第 2.3 节缓存及第 3 节验证；历史改造记录仅供追溯。跨仓库测试看任务清单“单轮会话框架联调验收”。
- 测量结果独立于特征快照，Worker 的 G 缓存只负责加速；当前 256 条上限不限制完整结果数量。现有 Job 串行与网格内部并行分开说明，LRU／多进程池仅作为后续优化。
- 实现状态更新需附代码入口或提交、契约／构建版本和验收记录。仅修改文档日期不表示代码已完成。
- 需求只在统一台账逐行维护，映射文档维护工程定义，任务文档维护交付与验收；用来源编号和任务 ID 关联。
